# 5.0 migration

Package is `com.dbflow5`. The library is Kotlin Multiplatform. Codegen is a **compiler plugin**, not KAPT or KSP.

## Breaking changes

| 4.x / early 5.x | Now |
| --- | --- |
| `kapt` / `annotationProcessor` `processor` | plugin `com.dbflow5` + `com.dbflow5:compiler` |
| `FlowManager.init(context)` | `createDB<AppDatabase>(context) { … }` |
| `database<App>()` / `databaseForTable<T>()` | Hold an `AppDatabase` instance |
| `model.save(db)` | `db.writableTransaction { userAdapter.save(model) }` |
| `@Database` name / inMemory | `DBSettings` on `create` |
| `@Database` without `tables =` | List tables, views, queries, migrations |
| Separate `coroutines` artifact | In `lib` |
| Java models / KAPT | Kotlin only |
| Model cache / `FlowCursorList` | Removed; use queries + `toFlow` |
| `GeneratedDatabaseHolder` reflection | `createDB` registers adapters; no holder factory |
| `*_Table` / `*CompanionBase` / `adapterDelegate` | Companions extend `ModelAdapterImpl` directly; column properties on the companion |
| `@QueryModel` | `@Query` |
| `DatabaseWrapper` | `DatabaseConnection` / transaction scopes |

## Database class

```kotlin
@Database(version = 1, tables = [User::class])
abstract class AppDatabase : DBFlowDatabase<AppDatabase>() {
    abstract val userAdapter: ModelAdapter<User>
}
```

`createDB` registers `User.Companion as ModelAdapter<User>` (and the same pattern
for views and query models). The companion is the adapter — there is no separate
generated base class or `adapterDelegate` property.

## Open

```kotlin
val db = createDB<AppDatabase>(context) { copy(name = "App") }
```

## Writes and reads

```kotlin
db.writableTransaction {
    userAdapter.save(user)
    (userAdapter.select() where (User.name eq "Ada")).list()
}
```

## Gradle

Remove `kapt` / KSP for DBFlow and apply the `com.dbflow5` plugin — that is the entire setup. The plugin adds the `lib` dependency, the compiler plugin, the generated-sources directory on `commonMain`/`main`, native `-lsqlite3` linker opts, and a `dbflowGenerate` task that keeps generated code in sync. See [install](including-in-project.md).

## Still true from earlier 5.0 alphas

- `save` is `INSERT OR REPLACE`
- `@Table(allFields = true)` by default
- `@Fts3` / `@Fts4`
- `TableObserver` drives `toFlow`, LiveData, Paging, and Rx
- WAL via `JournalMode` (automatic on capable devices)
